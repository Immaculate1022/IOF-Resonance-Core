# Contributing to IOF Resonance

Thank you for helping improve IOF Resonance. Contributions may include documentation corrections, reproducible experiments, visualizations, implementation improvements, and well-scoped bug fixes.

## Before You Begin

Please review the [README](README.md), search existing issues, and open an issue before starting material changes. Describe the problem, intended approach, and affected files so the work can be discussed before implementation.

## Development Expectations

Keep pull requests focused and small enough to review. Explain the purpose of the change, how it was tested, any dependencies introduced, and any limitations or assumptions. Do not commit credentials, private data, generated binaries, or large files that do not belong in source control.

For code changes, preserve the existing style where practical and add or update tests when a testable behavior changes. For research claims and technical documentation, distinguish hypotheses from validated results and link to sources, calculations, or reproducible evidence where available.

## Pull Requests

Use a descriptive title and include a brief summary, validation steps, and any relevant issue reference. By submitting a contribution, you confirm that you have the right to share it under the repository's existing license terms.

## Security Issues

Do not report potential vulnerabilities through public issues. Follow the repository's [Security Policy](SECURITY.md) instead.
